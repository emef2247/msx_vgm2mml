# MMLの同期ポイント

`vgm2mml.py` が生成する統合ファイル `<stem>.mml` は、全音源のMMLを結合した後、
各チャンネルの累積stepを計算して共通の同期ポイントをコメントで表示します。
後処理スクリプトの実行や追加オプションは不要です。

コメントが過密にならないよう、既定では前に採用した同期点から1000step以上離れた
最初の、ループ・マクロを分割しない共通同期点を選びます。開始0と曲の終端は間隔にかかわらず表示します。
例えばループ外の共通境界が12stepごとなら、0 → 1008 → 2016 → … となります。
1000stepちょうどの位置で音符を切ることはありません。
`--sync-min-gap 700` で間隔を変更でき、`--sync-min-gap 0` でループ・マクロを維持できる全同期点を表示できます。
これはコメントの表示密度の指定で、フレーズや小節の検出ではありません。

```mml
; ch1 --- step 0 : start ---
1 c%6 d%6
; ch1 --- step 12 : end ---

; ch4 --- step 0 : start ---
4 g%12
; ch4 --- step 12 : end ---
```

途中の同期点は `; ch1 --- step 48 : token-boundary 7/7ch ---` の形式です。
その時刻まで演奏が続く全チャンネルで、音符または休符の境界が揃う位置だけを採用します。
すでに演奏が終了したチャンネルと、音長を持たない設定専用チャンネルは以後の判定から除外します。
開始は0、最後は最長チャンネルの終了stepです。終了したチャンネルに休符は追加しません。
タイで連結された音の途中には同期点を設けません。

stepは出力MMLの時間単位で、四分音符が48stepです。VGMサンプル数やSegmentのtick数ではありません。
通常出力と `--raw-ticks` ではテンポと音長の表現が異なるため、同じVGMでもstepの値が異なります。
音符・休符の長さや音源解析は変更しません。

繰り返しやマクロ呼び出しの内部は同期候補から除外し、元の構造を保持します。
同期点を含まない繰り返しは維持します。
統合MMLの `#alloc` は総量15000を、出力された各演奏チャンネルのMML文字数
（空白・コメント・行頭のチャンネル番号を除く）の比率で配分します。
整数化の余りは小数部分の大きい順に配り、合計を15000に合わせます。
休符のみ、または全音符が音量0のチャンネルは統合MML本文と同期判定からも除外します。
これはコンパイル後の実測バイト数ではなく使用量の推定値です。
コメントのない通常の折り返し行もあり、すべての改行が同期点というわけではありません。

実装は `py/mml_sync.py` に分離しています。対象は本コンバーターが生成する旋律MMLで、
汎用MGSDRVパーサーではありません。未対応構文や無限ループは推測せずエラーにします。
`vgm2mml_grid.py` とデバッグ用の音源別MMLの出力形式は変更していません。
`--debug --dump-passes` による音源別MML、イベントCSV、PASS、Segmentの出力も引き続き利用できます。

検証ではコメント挿入前後の繰り返し・マクロを展開して、音符とコマンドの順序・開始step・終了stepを比較します。
提示サンプル `cpebach_fine_grained.mml` の全同期候補は `0, 4490, 4538, 4778` です。
最小間隔1000では `0, 4490, 4778` を表示します（最後は終端のため例外）。
VGMから新たに変換したMMLは、既存の変換処理が作る音符境界に基づくため、このサンプルと同じstepになるとは限りません。

## PSG/SCCの休符とソフトウェアエンベロープ

`py/mml_envelopes.py` はSegmentを変更せず、MML用の発音区間を組み立てます。
休符中は音量・モード・波形・音程などを出力せず、次の発音区間の設定をその直前に反映します。
連続する休符をまとめますが、その長さと発音開始時刻は保持します。

音程・波形・モードが一定の区間から音量推移を抽出し、再利用する `@e` 定義へ変換します。
音量の上昇を再アタック候補として区切り、周波数書き込みやPSGハードエンベロープ再設定も境界にします。
これは発音区間の保守的な推定で、VGMに音符情報が直接含まれるという意味ではありません。
ハードエンベロープはソフトウェアエンベロープへ置き換えません。

定義は `@eNN = { 0, 0, A:2, 8:2, 6:2 }` のような明示的な音量保持で、
適用時は `v15` を使います。PSGのモード・ノイズは個別指定し、定義による変更を避けます。
一定音量へ戻るときはF一定の定義に戻します。期待MMLの `F, E, 8=12` のような
補間パラメーターを逆算する処理は行わず、60Hz tickごとの観測音量を保持します。
エンベロープの時間単位は60Hzのままで、通常出力のMML音長の3倍表現とは分けます。

定義番号はPSG/SCC共有で0～31、同じ音量推移を重複登録しません。
定義枠不足や長すぎる定義は、音量コマンドとタイ付き音符で表現します。
`--dump-passes` の `*.target_notes.csv` はチャンネル・開始/終了tick・採用した定義番号・
元の音量推移を示します。`*.target.mml` には適用した定義と音源別本文を保存します。
既存のイベント、PASS、Segmentと、`--debug` の従来レンダラー出力も保持します。

## ループ・マクロの保持

全パート共通で、最上位の音符・ループ・マクロ呼び出しの境界だけを同期候補にします。
反復途中の音符境界や各周回の境界は、元のループ内部にある限り候補にしません。
入れ子ループも外側全体を保持し、コメントのための展開は行いません。
タイ途中も従来どおり候補から除外します。演奏終了済みのチャンネルは後続の候補を妨げません。

対象はPSG、SCC、OPLLメロディおよびOPLLリズムです。安全な共通境界がなければ
コメント間隔が指定値より長くなり、開始・終端だけになる場合もあります。
音符・音長・ループ回数・設定コマンドは変更しません。物理行の折り返しは継続します。
