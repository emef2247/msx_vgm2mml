# VGMからMGSへのバッチ変換

## デフォルトの閾値を明示したエクスポート用エントリーポイント

`export_mgs.py` は、`--fm-state-ms 24` と `--normalization-ms 8` をデフォルト値として、バッチ変換と同じ実装・診断機能を使用します。

```sh
python scripts/export_mgs.py INPUT_DIR --outdir OUTPUT_DIR --force
```

単一のVGM/VGZファイルも指定できます。閾値は、例えば `--fm-state-ms 4 --normalization-ms 16` のように個別に変更できます。これらのデフォルト値はオプションの正規化を要求するものですが、OPLLを基準とした安全な投影が見つからなければ、変換器は `unchanged` と報告します。PSG/SCCのエンベロープをフィルタリングするという意味ではありません。

従来の `batch_vgm_to_mgs.py` は、これまでの変換デフォルト値を維持します。どちらのエントリーポイントも出力構成は共通です。最終的なMML/MGSは各パッケージの `tracks/` に直接配置し、レポートや作業ファイルはパッケージ内の `_diagnostics/<stem>/` に保存します。エクスポート用エントリーポイントは、変換、コンパイル、省略ルール、レポート生成をバッチランナーに委譲します。正確なパス、PSGモード用ディレクトリ、再実行時の動作は[出力構成](output_layout.md)を参照してください。`--skip-keyon-counts` を含むその他のオプションの意味も共通です。オプションのKey-On検証は、明示的にスキップしない限り有効です。

両エントリーポイントとも、`INDIR` からの相対的な親ディレクトリ構造を `OUTDIR` 以下に保持します。例えば `INDIR/vgmrips.net/SALAMD/SONG01.vgm` は、`OUTDIR/vgmrips.net/SALAMD/tracks/SONG01.mml` と `.mgs` を生成します。`--outdir` を省略すると、代わりに `INDIR/vgmrips.net/SALAMD/` をパッケージのルートとして使用します。

PATH上にネイティブ版 `mgsc` があれば、そちらを優先します。その場合 `mgsc-js` は不要です。ネイティブ版の呼び出し形式は `mgsc INPUT.mml OUTPUT.mgs` です。実行ファイルを明示するには `--mgsc /usr/local/bin/mgsc` を指定します。

```sh
python scripts/batch_vgm_to_mgs.py tests/fixtures/local_only/opll --outdir outputs/mgs
```

変換成功の条件は、終了コードが0であり、今回の実行で空ではないMMLが生成されることです。コンパイル成功の条件は、終了コードが0で、かつ出力MGSが空でないことです。一部のネイティブ版ビルドはMMLエラーでも0を返すためです。失敗時の標準出力・標準エラー出力はコンソールに表示し、ログにも記録します。生成済みMMLは調査用に残します。

ネイティブ版コンパイラが見つからない場合は、Windowsやmsxplayとの互換性のため、従来のJavaScript版へのフォールバックを利用できます。`--mgsc-module` を明示すると、`--mgsc` も指定されている場合を除きJavaScript版が選択されます。Node.jsとオプション依存パッケージをインストールしてください。

```sh
npm install --no-save --package-lock=false mgsc-js@2.0.0
python scripts/batch_vgm_to_mgs.py tests/fixtures/local_only/opll --outdir outputs/mgs
```

代わりに `--mgsc-module /absolute/path/to/mgsc-js/dist/index.js` を指定することもできます。コンパイルだけならlibkssへの依存は不要です（`--skip-keyon-counts` を指定）。出力先を明示する場合、そのディレクトリツリーは入力とは別にする必要があります。`--outdir` を省略すると、最終MML/MGSは各VGMの隣の `tracks/` に配置されます。診断情報は各パッケージの `_diagnostics/<stem>/` 以下に保存されます。単一ファイル入力では、そのファイルの親ディレクトリがパッケージのルートになります。隣接する出力への再実行時は、生成済みの診断ディレクトリとPSGモード用ディレクトリを入力探索から除外します。変換前に、Node.jsがMGSCを読み込んで初期化できるか確認します。`mgsc-js` の欠落は環境構築エラーであり、MMLコンパイルエラーではありません。WSLでは、このリポジトリ内でWSLからnpmインストールを実行してください。グローバルインストールだけではヘルパーのモジュール解決に不十分です。

ツールは `.vgm` / `.vgz` を再帰的に検索し、相対的な親ディレクトリ構造を維持します。最終成果物は `<out>/<relative-parent>/tracks/<stem>.mml` と `.mgs` です。曲ごとの追加の試聴用ディレクトリは作成しません。作業領域、ログ、付随ファイルは `<out>/<relative-parent>/_diagnostics/<stem>/` に保存します。各パッケージには `_source_inputs/` に配置した元ファイル、試聴用マニフェスト、パッケージ相対の結果情報が含まれます。PSG単独モードでは、相対親ディレクトリの前に `psg_melody/` または `psg_rhythm/` が追加されます。元ファイルは変更しません。再実行時には、公開マニフェストに記録された未変更の成果物を置き換えます。編集されたファイルや管理対象外のファイルがある場合は、明示的な衝突エラーにします。再実行が失敗した場合は、以前生成した管理対象の試聴用ファイルを保持し、最新の失敗を別途報告します。

`_diagnostics/results.csv` と `results.json` は入力ファイルを1つ処理するたびに更新されます（PSG単独実行では対応するモード配下）。後続の入力で処理が中断しても、完了済みの進捗は保持されます。主なステータスは `success`、`conversion_failed`、`compilation_failed` です。`stage` と `error_code` により、変換エラー、コンパイラのバッファエラー、出力欠落、プロセスエラー、タイムアウトを区別します。該当する場合、`legacy_status` に以前の分類を保持します。コンソールには `input: status: detail` を表示し、最後にエクスポート件数を表示します。失敗しても後続の入力処理は継続します。領域割り当ての調整、自動再試行、楽曲の切り詰めは行いません。`--timeout` は各処理段階のタイムアウトを秒単位で設定します（デフォルト1200秒）。タイムアウト時も途中までの標準出力・標準エラー出力を保持します。コンパイルに失敗した不完全なMGSは削除しますが、中間MMLは調査用に残します。MGSのコンパイル成功は再生結果の同等性を保証しません。

各入力の診断フォルダには `report.json` と `report.txt` があり、実際に適用されたオプション、各段階のコマンド、出力パス、エラー詳細、生ログのパスを記録します。正規化とFM状態の付随情報は `summaries` に組み込まれます。CSV/JSONの各行にも `normalization_status`、`normalization_reason`、`normalization_ms`、`fm_state_ms` を記録するため、指定された設定と実際の適用状況を区別できます。再実行時に置き換えるのは、その入力について既知の生成済みMML/MGS、レポート、段階別ログ、正規化・force関連の付随ファイルだけです。無関係なファイルやディレクトリは保持します。ディレクトリの代わりに単一の `.vgm` / `.vgz` ファイルも指定できます。

## 共通の変換オプション

`--fm-state-ms` は内部のOPLL状態閾値を渡します（デフォルト1 ms）。`--normalization-ms` は音長正規化の閾値を渡し（デフォルト8 ms）、正規化を有効にします。`--fm-state-ms` を明示した場合も正規化が有効になります。`--normalize-lengths` はデフォルト閾値で正規化を有効にします。MSX変換器の正規化は引き続き明示指定方式です。これらの値は異なる処理パスを制御し、別々に記録されます。`--dump-passes` は変換途中の各パスを調査可能な形で保存します。不正な閾値やタイムアウト値は、環境設定や出力の変更前に拒否されます。

`--force` が有効にするのは、変換器のドキュメントで定義されたターゲット向け省略ルールだけです。`<stem>.mgs.force.json` が生成された場合、コンソールと入力レポートに省略件数と詳細ファイルのパスが表示されます。不正な入力、コンパイラのバッファ制限、依存関係の欠落、タイムアウトを回避するものではありません。許可されるルールは変換器のforce関連ドキュメントを参照してください。コンパイル成功だけでは同等の再生を保証しません。

`--software-volume-curves` は、音程が固定されたPSG/SCCの音量カーブを、共有ソフトウェアエンベロープへ厳密に投影する処理を要求します。明示指定が必要で、タイミング正規化とは独立しています。損失を伴う時間フィルタリングは行いません。チップごとの `<stem>.<chip>.volume_curves.json` の要約は診断情報として保持され、`report.json` にも含まれます。`--dump-passes` を指定すると、候補、ノート、判定に関するCSVも調査用に保存されます。

## 統合されたOPLL Key-On回数の検証

デフォルトでは、コンパイルに成功した各MGSをlibkssで `<stem>.roundtrip.vgm` にエクスポートし、元のVGMと比較します。この検証のためにVGM→MML変換やMGSコンパイルを繰り返すことはありません。リポジトリ内にオプションの再生用依存パッケージをインストールします。

```sh
npm install --no-save --package-lock=false libkss-js
python scripts/batch_vgm_to_mgs.py tests/fixtures/local_only/opll --outdir outputs/mgs
```

代わりに `--libkss-module /absolute/path/to/libkss-js/dist/index.js` も指定できます。ネイティブ版MGSCを使用する場合でも、再生にはNode.jsが必要です。従来の変換・コンパイルのみの動作にするには `--skip-keyon-counts` を指定します。

`results.csv` と `results.json` には、`reference_keyon`、`actual_keyon`、`missing_keyon`、`extra_keyon`、`keyon_status`、`keyon_error` も含まれます。コンパイルの `status` は独立して扱われます。`keyon_status` は `compared`、`mismatch`、`selection_only`（PSG単独エクスポート。ネイティブOPLLの一致判定は適用外）、`not_compiled`、`unavailable`（依存関係の問題）、`timeout`、`error`、`disabled` のいずれかです。比較を実行していない場合、回数は捏造したゼロではなく空欄になります。回数の差異があってもコンパイル自体は失敗扱いになりません。ただし、変換・コンパイルが失敗した場合、有効な比較が完了できなかった場合、または通常のメロディパートの回数が一致しない場合、終了ステータスは1になります。PSG単独エクスポートが成功した場合は `selection_only` になります。

`keyon_setup.log` は再生の初期設定を記録します。成功した各エクスポートではVGM、`keyon.log`、および双方のトレース、キーの立ち上がり・立ち下がり、要約JSONを格納する `keyon/` フォルダを保持します。このバッチでの回数検証ではSegmentの再構築を省略しますが、単独の比較コマンドでは詳細なSegmentダンプを引き続き利用できます。

再生は1回（`loop: 1`）行い、安全のための再生時間上限は元VGMヘッダーの総サンプル数に25%と2秒を加えた長さです。元データの再生時間がゼロの場合や、エクスポートが時間上限に達した場合は、誤解を招く回数を提示せず「未完了」と報告します。タイムアウトやエラーが影響するのはその比較だけで、後続の入力処理は続行します。[Key-On回数の定義](opll_keyon_counts.md)を参照してください。

オプションの変換リグレッションは、WBIII01..14、ThBSMS01..05、YsSMS01..20、Alest201..217を対象とします。ローカルファイルがなければ個別にスキップし、非公開データは含めません。実行コマンドは `python -m unittest discover -s tests/script -p test_local_opll_catalog.py` です。

`--normalize-lengths` は、オプションの音楽的な音長補正を各変換に適用します。デフォルト値は変更せず、変換を二度実行することもありません。入力ごとの `convert.log` と `<stem>.normalization.json` に適用済み／未変更の状態を記録します。コンパイル済みMGSとKey-On比較は同じ出力を使用します。[正規化の動作と制約](note_normalization.md)を参照してください。

## 圧縮方式の比較

変換器では、構造的なPSG/SCC/OPLLループと強化されたマクロがデフォルトで有効です。PSG/SCCの構造化は、ソフトウェアエンベロープの選択より先に行います。従来の圧縮方式を使用するには、このバッチスクリプトに `--legacy-loops --legacy-macros` を指定します。比較時は出力先ディレクトリを分けてください。これらのスイッチで、過去のチャンネル配置や文字コードの不具合が再発するわけではありません。強化された候補選択は旧コンプレッサーより時間がかかるため、大きな入力では `--timeout 900` が必要になる場合があります。

古いUTF-8のMGSタイトルは、その場では修復されません。現在のパイプラインで変換とコンパイルを再実行すると、CP932のタイトルが生成されます。

## オプションのOPLLドラム推定

`--enhance-drums` を使用すると、PSG/SCCを保持したまま、推定したOPLLリズムパートを追加します。この実験的オプションはデフォルトで無効です。候補とターゲットの判定は `.drums.*` のCSV/JSONレポートに保存されます。既存のOPLLメロディ／リズムが優先されます。分類とタイミングの制約は[ドラム強化](drum_enhancement.md)を参照してください。

## 再生検証と初期設定データの終端

生成される定義データの領域割り当てには、ストリームの終端バイトも含まれます。MGSCでのコンパイル成功だけでは、過去に発生した終端バイト欠落による無音問題を検出できません。[定義データの格納と再生確認](mgs_definition_storage.md)を参照してください。OPLLの回数が一致しない場合、バッチはコンパイル結果を保持しつつ `keyon_status=mismatch` を記録し、差分を表示して、エクスポート処理をゼロ以外の終了コードで終了します。回数が一致しても、それは音声や楽曲全体の同等性より限定的な証拠です。

最終的なタイ補正、共有バンクの検証、未対応のクロック／分割スケジュールに対する明示的なフォールバックについては、[ソフトウェア音量カーブ](software_volume_curves.md)を参照してください。
